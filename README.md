# HERMES-CONSOLE

Видимый интерактивный консольный мост для Windows-сервера: реальный окно `cmd.exe`
на рабочем столе сервера (сессия 1), которым управляет агент через SSH-туннель.
Никаких фоновых/скрытых сессий — всё видно глазами на мониторе.

> **Полное описание проекта — зачем он, что делает каждый файл и какая логика заложена: [DESCRIPTION.md](DESCRIPTION.md)**

## Состав

| Файл | Что делает |
|---|---|
| `scripts/hermes_bridge.ps1` | Мост: владеет окном консоли, инжектит реальные клавиши (`WriteConsoleInput`), читает экран/скроллбэк (`ReadConsoleOutput`), настраивает внешний вид окна, хранит и восстанавливает историю. Один процесс = одна вкладка (tab N слушает `PORT+N-1`) |
| `scripts/hermes_tray.ps1` | Трей-апплет у часов: иконка-светофор (оранжевый = готов, зелёный мигает = агент работает, жёлтый = мост занят, красный = мёртв), воркер-ранспейс следит за ВСЕМИ вкладками и перезапускает мёртвые; меню **Tabs** + диалог «New tab...» + **панель вкладок** в стиле Chrome (полоса вкладок с точками статуса и дерево процессов каждой вкладки: мост → cmd → серверы внутри) |
| `scripts/hermes_console_client.py` | Клиент с Mac: `hb`, `wd`, `state`, `screen`, `history`, `keys`, `show`, `hide`, `ping`, `quit`, `tabs`, `newtab`, `closetab`; адресация вкладки через `--tab N` |
| `scripts/console_up.sh` / `console_down.sh` | Подъём/разборка связки «туннель + таск + трей + мост» как одного юнита |
| `scripts/install_server.sh` | Установка на НОВЫЙ сервер одной командой: проверки → копирование (CRLF) → конфиг из примера → задача планировщика → end-to-end пинг |
| `scripts/console.cfg.example` | Шаблон конфига клиентской стороны (хост/порт/способ туннеля) |
| `scripts/hermes_console.cfg.example` | Шаблон конфига серверной стороны (BIND/PORT/WORKDIR) |
| `scripts/hermes_console.bat` | Ручной запуск окна двойным кликом |

## Протокол (v2, уникальные префиксы)

```
запрос   : HERMES-REQ-8F27:<json>
полезная : HERMES-RES-8F27:<line>   (повторяется)
конец    : HERMES-DONE-8F27:<op>    (ровно один на запрос)
```

Мост по умолчанию слушает `127.0.0.1:18799` — адрес и порт настраиваются конфигом
(см. «Конфигурация» ниже), а не кодом. Вкладка N слушает `PORT+N-1` (диапазон пробрасывается туннелем).

## Принципы, зафиксированные владельцем

- `keys` **никогда не спит**: инжект и ответ за миллисекунды, мост отвечает на `hb`
  во время любой долгой команды. Долгие команды — опросом `screen`/`history`.
- Иконка не врёт: живой, но молчаливый мост = жёлтый BUSY, а не красный DOWN.
- История скроллбэкa пишется на диск (`E:\LOCAL_HERMES\hermes_history.txt`, 400 строк)
  и проигрывается в новое окно после перезапуска моста — «как будто ничего не случилось».
- Крестик у окна мёртв (`DeleteMenu(SC_CLOSE)`): закрытие — только через трей.
- Размер и позиция окна **запоминаются**: ручной фуллскрин/ресайз/перемещение переживают
  Hide→Show и перезапуск моста (файл `hermes_geom.txt`); дефолт `1366x844` — только при первом запуске.
  Шрифт `Lucida Console 6x10`, буфер `87x9999`,
  окно `87x16`, цвета `0x1F` (белый по синему, через `color 1f`).
- Рабочая папка: `E:\AI`.

## Конфигурация (перенос на другой сервер — без правок кода)

- **Клиент/up-down:** `scripts/console.cfg` (шаблон `console.cfg.example`, сам файл в `.gitignore`):
  `HOST` (SSH-цель), `KEY`, `PORT`, `TUNNEL=ssh|none` (`none` — туннель реализован иначе:
  cloudflared, Tailscale serve, socat, открытый порт), `HC_HOST` (адрес моста с этой машины),
  `EXPECT_HOST` (проверка идентичности сервера), `PS1_DIR` (папка скриптов на сервере).
  Переменные `HC_*` перекрывают файл; клиент также принимает `--host/--port`.
- **Сервер:** `hermes_console.cfg` рядом с .ps1 (шаблон `hermes_console.cfg.example`):
  `BIND` (адрес прослушивания моста), `PORT`, `WORKDIR`, `BRIDGE_BIND`. Переменные `HERMES_*` перекрывают.
- **Трей-меню (без правки файлов вообще):** раздел **Endpoint** — текущий `host:port` в подписи,
  «Auto-detect on this PC» (перебирает локальные слушатели, проверяет каждый протокольным `hb`-пробом —
  считается только ответ `pong`) и «Set host:port manually...» (диалог ввода). Выбранный эндпоинт
  применяется мгновенно и сохраняется в `hermes_console.cfg`, чтобы мост после авторестарта слушал там же.
  Результат автодетекта показывается **всплывающим уведомлением у часов** (найден и применён / ничего
  не найдено), а если адресов с ответом несколько — открывается **окно выбора с кликом** по адресу.
  В самом меню нет строк-подсказок и строк статуса: меню — только действия, статус говорит цвет иконки.
- **Вкладки (несколько рабочих консолей одновременно):** у одной Windows-консоли ровно одна
  очередь ввода — пока в окне работает долгоживущий сервер (например `START.bat` → ComfyUI),
  ввести другую команду в это же окно физически нельзя, не прервав сервер. Поэтому каждая вкладка —
  это отдельный мост: своё окно `cmd.exe`, свой процесс, свой порт `PORT+N-1`, своя история и своя
  геометрия окна (файлы с суффиксом `_tN`; вкладка 1 сохраняет старые имена без суффикса).
  Вкладки создаёт/закрывает трей (он живёт в интерактивной сессии 1 и может поднять видимое окно);
  мост из сессии SSH просит его через шов `tray_cmd.txt` (`newtab`/`closetab`).
  Меню трея: **Tabs** (показать/спрятать/перезапустить/закрыть каждую), **«New tab...»** (метка + папка).
  Клиент: `--tab N` перед любой командой, команды `tabs` (обход диапазона портов), `newtab "метка" "папка"`,
  `closetab N`. `TABS=8` в конфиге — максимум. Свип зомби-окон при старте вкладки **tag-aware**:
  окна с меткой `[Tn]` живой вкладки не закрываются, иначе соседние вкладки гибли бы при старте новой.
- **Панель вкладок** (`Tabs panel (browser-style)` в меню трея, удалённо — `!panel` в `tray_cmd.txt`):
  окно `HERMES-CONSOLE - tabs` с хромовской полосой вкладок (точка статуса, крестик, «+») и деревом
  процессов выбранной вкладки (PID/CPU/RAM). Клик — фокус консоли, двойной клик — show/hide. Панель
  читает только кэш воркера и ставит команды в очередь; дерево воркер собирает снимком Toolhelp32.
- **Папка по умолчанию прямо из трея:** раздел **Folder** — метка текущей папки и пункт
  «Set default folder...» (нативный выбор папки). Путь сохраняется в `hermes_console.cfg`
  (`WORKDIR=`) и мост сразу перезапускается в новой папке (история консоли при этом не теряется).
  Путь, указывающий на файл, отклоняется с предупреждением; несуществующая папка создаётся мостом.
  Текущая папка — в тултипе иконки и проверяется фактом: оп `wd` у моста и `wd` в клиенте.
- **`keys` = «набрать и выполнить»:** клиент и мост сами дописывают Enter в конец текста
  (передать `"enter":0` в JSON, если нужно набрать без запуска). Раньше без этого набранная строка
  оставалась на линии ввода, а проверка «маркер появился в screen» давала ложный успех по тексту
  самой команды.
- Пути логов/истории/соседних скриптов — относительно папки скриптов: разворачивать можно куда угодно.
- **Установка на новый сервер одной командой:** `bash scripts/install_server.sh` — проверяет SSH и
  идентичность сервера, создаёт/проверяет запись в `PS1_DIR`, копирует скрипты с LF→CRLF,
  создаёт `hermes_console.cfg` из примера (существующий НЕ трогает), регистрирует задачу
  `HERMES-CONSOLE` и проверяет факт (задача видна, мост отвечает). Идемпотентен: повторный запуск
  обновляет файлы, но не трогает живой стек и существующий конфиг.
